01 · Why

모델을 잘 고르는 것만으로는 부족합니다.

Routing, coding agent, validation이 따로 움직이면 조직 정책과 실제 성공 기준, 총비용을 한곳에서 관리하기 어렵습니다.

“성공했다”는 model의 답이 아니라, 같은 acceptance gate를 통과한 결과가 필요합니다.

이 repository는 기존 coding agent와 provider 사이에 governance layer를 둡니다. 특정 vendor를 대체하기보다 실행 기준을 고정합니다.

Router
요청별 model 선택과 fallback을 담당합니다.
Coding agent
Repository를 읽고 파일을 수정하거나 command를 실행합니다.
Validator
Build·test·lint exit code로 결과를 판정합니다.
Control plane
정책, validation escalation, 실패 비용, body-free trace를 하나의 run contract로 묶습니다.

05 · Security boundary

Policy runner이지, OS sandbox는 아닙니다.

현재 code가 강제하는 경계와 production에서 별도로 필요한 경계를 구분합니다.

Code에서 강제

  • Structured argv와 shell=False
  • Executable·Python module allowlist
  • Workspace path와 network target 차단
  • Timeout·output 초과 시 process-group 종료
  • Protected validator/test integrity 검사
  • Cost·attempt·wall-time hard limit

Production에서 별도 필요

  • Container 또는 microVM 격리
  • Bridge별 egress policy와 least privilege
  • Provider invoice와 usage reconciliation
  • Signed configuration과 protected review path
  • 실제 coding task와 외부 팀 validation
  • Retention·deletion·incident response policy

06 · Quick start

Offline evidence부터 실행합니다.

Runtime dependency는 없습니다. Dev tools를 설치한 뒤 escalation demo와 comparative benchmark를 바로 재현할 수 있습니다.

01 / setup
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
02 / verify escalation
# Validation failure → stronger model → cost ledger
.venv/bin/python -m agent_control_plane.cli demo \
  --workspace /tmp/agent-control-plane-demo

# Policy routing vs always-strong offline baseline
.venv/bin/python -m agent_control_plane.cli benchmark
03 / full gates
.venv/bin/python -m compileall -q src tests examples
.venv/bin/ruff check src tests examples
.venv/bin/mypy src
.venv/bin/bandit -r src -ll
.venv/bin/python -m pytest -q

Clean-room boundary

기능을 참고하되, source를 복사하지 않았습니다.

Routing, coding agent, repository execution 분야의 공개 프로젝트를 capability별로 검토한 뒤 독립 interface와 implementation으로 작성했습니다. 외부 프로젝트는 각자의 license와 terms를 따릅니다.
